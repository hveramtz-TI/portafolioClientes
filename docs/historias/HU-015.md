# HU-015 — Desactivar rubro (oculta servicios, conserva historial)

**Épica:** Rubros, categorías y servicios
**Prioridad:** Media
**Estado:** Aprobada
**Fecha:** 2026-08-19

## Descripción

Como usuario, quiero desactivar un rubro de mi catálogo personal que tiene categorías, servicios u órdenes relacionadas, para ocultarlo sin perder historial.

## Criterios de Aceptación

- [ ] Un rubro con relaciones (categorías, servicios, órdenes) se desactiva (`status = 'desactivado'`), no se elimina físicamente.
- [ ] Al desactivarlo, sus categorías y servicios dejan de mostrarse en el perfil público (scope `whereStatus('activo')`).
- [ ] El historial de órdenes se conserva intacto.
- [ ] El rubro puede reactivarse posteriormente (`status = 'activo'`).
- [ ] Aplica tanto a rubro base como a fork personal (`user_catalog_items`).
- [ ] Desactivar rubro en cascada: categorías y servicios heredan `status = 'desactivado'` (o se filtran por rubro desactivado en queries).

## Notas / Dudas

- La eliminación definitiva de rubros sin relaciones se trata en HU-016.
- Modelo híbrido: `status` enum (`activo`, `desactivado`) + `SoftDeletes` trait para hard delete (HU-016). Desactivar no usa `deleted_at`. Scope global filtra `status = 'activo'` para perfil público. Reactivación restaura visibilidad.
