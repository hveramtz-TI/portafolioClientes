# HU-025 — Copia personalizable del catálogo por usuario (sin alterar la base)

**Épica:** Rubros, categorías y servicios
**Prioridad:** Alta
**Estado:** Aprobada
**Fecha:** 2026-08-19

## Descripción

Como usuario, quiero personalizar mi catálogo (fork) sin alterar la base precargada ni afectar a otros usuarios, para ajustar los servicios a mi caso.

## Criterios de Aceptación

- [ ] Cada usuario trabaja sobre su fork personal almacenado en `user_catalog_items` (polimórfico: rubro/categoría/servicio).
- [ ] Editar, crear o eliminar en mi fork no modifica el catálogo base (tablas `rubros`, `categorias`, `services`).
- [ ] Los cambios de un usuario no afectan a otros usuarios (aislado por `user_id`).
- [ ] Al seleccionar un rubro base, el sistema crea entrada en `user_catalog_items` tipo 'rubro' + copia en cascada de sus categorías y servicios base como items del usuario.
- [ ] Usuario puede sobrescribir (override) nombre, descripción, valor, tags en su fork sin tocar base.
- [ ] Usuario puede crear nuevos rubros/categorías/servicios solo en su fork (`base_id = null`).
- [ ] Eliminar en fork → elimina recursivamente el item y sus hijos de `user_catalog_items`; base intacta. Eliminar base → solo admin/seeder, si no tiene relaciones ni forks.
- [ ] Herencia dinámica: si base cambia y usuario no tiene override → ve cambio base. Si tiene override → ve su versión.

## Notas / Dudas

- Tabla conceptual `user_catalog_items`: `user_id`, `item_type` (rubro|categoria|service), `base_id` (referencia polimórfica nullable, validada a nivel de aplicación), `parent_fork_id` (jerarquía canónica), `overrides` (JSON solo para name, description, value y tags), `status` (activo/desactivado), `sort_order`. **Flujo:** UI muestra árbol base + badges 'personalizado' en overrides. Selección rubro → POST `/api/user-catalog/rubros/{id}/fork` → crea fork completo en cascada. La visibilidad también considera todos los padres; reactivar no activa hijos desactivados.
